# 06 · 页面原型与信息架构

## 1. V1 信息架构（6 页）

```text
/app
  ├── /                     Dashboard
  ├── /audit                网站分析
  ├── /keywords             关键词机会
  ├── /content              内容机会
  ├── /geo                  GEO（AI 可见性）
  └── /advice               增长建议（今日）
```

辅助（可抽屉/模态，不必独立路由）：

- 接入向导（Onboarding）
- 机会详情
- Action Plan 预览
- 集成设置

## 2. 全局导航

```text
[Logo] Growth Agent
  Dashboard | 网站分析 | 关键词 | 内容 | GEO | 增长建议
                          [站点切换] [设置]
```

首屏原则：**先看「今天做什么」**，分数与图表是支撑，不是主角。

## 3. 页面规格

### 3.1 Onboarding（首次接入）

**目标**：最短路径拿到第一次 Audit + 建议。

```text
步骤 1  输入网站 URL
步骤 2  连接 Google Search Console（可跳过，能力降级）
步骤 3  连接 Google Analytics 4（可跳过）
步骤 4  开始扫描 → 进度（爬取 / 同步 / 分析）
步骤 5  进入 Dashboard
```

空态文案强调「增长员工」而非「SEO 报告」。

---

### 3.2 Dashboard

**一句话**：今天站点怎么样 + 最值得做的 3 件事。

**布局（上 → 下）**

1. **今日问候条**  
   `Good morning` + 一句话叙事（Analytics Agent）

2. **健康度条**（次要）  
   综合评分 + 分项：SEO / **GEO** / 技术 / 内容 / 覆盖 / 转化

3. **高优先级行动卡（最多 3）**  
   每卡：标题、证据一行、预期影响、CTA「查看方案」

4. **指标快览**  
   UV / 搜索流量 / CTR / 转化 + 环比；点击进 Analytics 叙事展开

**不要**：首屏堆满 issue 列表或大盘图表墙。

---

### 3.3 网站分析（Audit）

**一句话**：健康度与问题，但带「值不值得修」的语境。

**区块**

```text
综合评分卡片
  SEO 82 · GEO 58 · 技术 76 · 内容 68 · 覆盖 54 · 转化 61

问题分布
  🔴 严重 3 · 🟠 机会 17 · 🟡 潜在 42 · 🟢 优秀页 8

问题列表（可筛选）
  严重度 | 页面 | 说明 | 「业务影响」标签 | 转成机会
```

单页抽屉：Title / Description / H1 / Canonical / Schema / 内链摘要 +「生成该页优化方案」。

---

### 3.4 关键词机会

**一句话**：值得抢的词，而不是词库浏览器。

**表格/卡片字段**

| 关键词 | 当前排名 | 趋势 | 落地页 | 潜力 | 操作 |
| --- | --- | --- | --- | --- | --- |
| React Admin | #18 | ↑6 | /products/admin | ★★★★★ | 生成方案 |

详情面板：

```text
你的页面  VS  Top 意图要点（V1 可用规则摘要，V2 做 SERP 对比）
预计提升  #18 → #8~12
建议动作  ① 内容 ② FAQ ③ 内链 ④ Title ⑤ Schema
```

---

### 3.5 内容机会

**一句话**：该写什么、先写哪篇。

列表项：

```text
缺口标题
目标关键词 · 预估价值 · 建议路径 /blog/...
[生成内容 Brief]
```

Brief 预览：搜索意图、大纲 H2、**首段直接答案**、FAQ、内链目标页、竞品参考（V2）。

---

### 3.6 GEO（AI 可见性）

**一句话**：页面能不能被生成式引擎「抽出来、引得起」。

**区块**

```text
GEO 总分 + breakdown
  answerability · structure · trust · ai_access · entity

站点级
  robots 对 AI bot 策略摘要 · llms.txt 有/无

页面机会列表
  高价值页 | 缺失：定义段/FAQ/Schema | [生成 GEO 方案]
```

V1 明确标注：分数来自 **Readiness 规则**，不是「已被 ChatGPT 引用」实测。  
V2 增加「目标问题引用探测」面板。

---

### 3.7 增长建议（今日）

**一句话**：AI 员工的每日 standup。

完整复现产品叙事中的「今日增长建议」：

```text
今天发现 N 个值得处理的问题

🔴 高优先级
  …证据与建议…  [生成优化方案]

🟠 中优先级
  …             [生成 A/B 方案]

🟢 增长机会
  …             [查看关键词]
```

交互：

- 标记：已处理 / 稍后 / 忽略
- 生成方案 → Action Plan 面板（步骤清单、可复制文案）
- V1 无自动改站：CTA 为「复制修改项」或「导出 Markdown」

## 4. Action Plan 面板（跨页组件）

```text
机会标题
摘要与预计提升
步骤
  1. 修改 Title → 建议文案 [复制]
  2. 增加定义段 / FAQ → 草稿 [复制]
  3. 增加 Schema / llms.txt → 片段 [复制]
  4. 内链 → 源页 → 目标页列表
状态：草稿 / 已批准
[批准] [关闭]
```

V3 起增加：`创建 GitHub PR`。

## 7. 文案语气

- 像同事汇报，不像审计恐吓。
- 数字必须带来源语境（页面、关键词、时间窗）。
- 优先「建议做 X」，避免只报「得分 72」。
